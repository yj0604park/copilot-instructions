# 세션 오케스트레이션

> 여러 세션에 작업을 나눠 맡길 때 읽는다. 위임 프롬프트에 무엇을 넣을지, 언제
> 병렬로 돌릴지, 결과를 어떻게 검증할지.

**사용자와 대화 중인 세션은 오케스트레이터다. 긴 구현을 직접 붙잡지 않는다.**
사용자는 대화 중에 새 아이디어를 계속 던진다. 대화 세션이 구현에 매몰돼 있으면
그때마다 컨텍스트가 깨지고, 하던 작업 결과도 나중에 확인하기 어려워진다.

## 역할

- **오케스트레이터 (대화 세션)**: 아이디어 수집 → 문서화 → 작업 분해 → 위임 →
  결과 검증 → 사용자 보고. 사용자의 새 입력에 항상 즉시 반응할 수 있어야 한다.
- **워커 (child session)**: 하나의 작업을 진득하게 끝까지. 자기 worktree·브랜치를 가짐.

## 아이디어가 들어오면

1. **먼저 적는다.** 하던 일을 멈추고 30초 안에 해당 프로젝트의 백로그 문서에
   기록. 문서가 없으면 만든다. 프로젝트마다 **우선순위·백로그 문서 하나**를 두고
   그게 진행 보드다 (예: `docs/user-scenarios.md`의 우선순위 표).
2. **지금 할지 나중에 할지 정한다.** 사용자에게 순서를 묻거나, 명백하면 그냥 큐에.
3. 적기 전에 구현부터 시작하지 않는다. 적어두면 잃지 않는다.

## 위임은 `create_session` (서브에이전트 아님)

- 코드를 바꾸는 작업은 **child session**으로 위임한다. `task` 서브에이전트는
  끝나면 사라져서 나중에 결과를 열어볼 수 없다. child session은 사이드바에
  남고, 히스토리가 보존되고, 추가 지시를 보낼 수 있고, 자체 PR을 낸다.
- **읽기 전용 조사·탐색만** `task explore`로. 파일을 쓰는 순간 child session.
- `notify_on_idle: "once"`를 걸어 완료 알림을 받는다. 폴링하지 않는다.
- 위임 후에는 **다른 일을 하거나 사용자와 대화를 계속한다.** 기다리며 놀지 않는다.

## 위임 프롬프트에 반드시 넣을 것

child는 이 대화를 모른다. 다음이 빠지면 반드시 헤맨다.

- 목표 한 줄과 **완료 조건(DoD)**
- 참조할 설계 문서 경로 (`docs/...`의 몇 절인지까지)
- **검증 명령** (`npx tsc --noEmit`, `npx eslint .`, 스모크할 라우트 목록)
- 건드리면 안 되는 파일/범위
- 워크스페이스 준비 절차. worktree는 새 디렉터리라 `node_modules`도 로컬 DB도
  없다. 예: `npm install` → `npm run seed:demo -- --reset` → `PORT=31xx npm run dev`
  (같은 디렉터리에 dev 서버 중복 실행은 Next가 막으므로 포트를 겹치지 말 것)
- **보고 경로와 보고 항목** → 아래 "완료 보고는 경로를 지정해야 온다"

## 완료 보고는 경로를 지정해야 온다

child에게 "PR URL만 알려줘"라고 했더니 **자기 세션 화면에만 답을 쓰고** 부모에겐
아무것도 안 보냈다. 오케스트레이터는 URL을 못 받았고 사용자가 직접 찾아야 했다.
원인은 child의 불성실이 아니라 **어떤 경로로 보고할지를 안 정한 것**이다.

- **"알려줘"는 지시가 아니다.** 위임 프롬프트에 경로를 문장으로 박는다:
  "작업이 끝나면 `send_session_message`로 부모 세션(`session_id`: `<id>`)에 결과를
  보낸다." 부모 세션 id는 위임 직전에 오케스트레이터가 `list_sessions_and_chats`로
  확인해서 **그 값을 프롬프트에 직접 써 넣는다.** child는 부모가 누군지 모른다.
- **보고에 담을 내용을 항목으로 지정한다.** 예: PR URL, 브랜치명, 커밋 해시 목록,
  변경 파일 목록, 실행한 검증 명령과 그 결과, 못 한 것과 이유.
  "보고해라"만 쓰면 child는 서술형 요약만 남기고 정작 필요한 식별자를 빼먹는다.
- **`notify_on_idle`은 보고 수단이 아니다.** "끝났다"는 신호일 뿐 결과를 실어 오지
  않는다. 알림만 믿고 기다리면 아무것도 못 받는다.
- **그래도 안 오면 직접 확인한다.** `get_session`으로 상태를 보고, child worktree
  경로에서 `git log` / `gh pr list`로 결과를 캐낸다. 사용자에게 찾게 하지 않는다.
- **후속 지시에도 매번 적는다.** `send_session_message`로 보내는 추가 요청에도
  보고 경로를 다시 명시한다. kickoff에만 적어두면 후속 턴에서 잃어버린다.

## 병렬은 파일 충돌 기준으로

- 의존 없고 만지는 파일이 다르면 병렬 OK.
- **단일 거대 파일**(예: 앱 전체 스타일이 한 CSS 파일)을 여러 child가 동시에
  고치면 충돌한다. 그런 작업은 순차로.

## 검증은 오케스트레이터가 한다

- child가 끝났다고 하면 그대로 믿지 않는다. 해당 worktree에서 `git diff`를 읽고,
  typecheck·lint·스모크를 직접 돌린다.
- 사용자에게는 **무엇이 바뀌었고 무엇을 확인했는지**만 보고. 과정 나열 금지.
- 미흡하면 새 세션을 만들지 말고 `send_session_message`로 그 child에게 수정 요청.
  컨텍스트를 갖고 있는 쪽이 고치는 게 싸다.

## 예외

- 5분 안에 끝나는 소규모 수정, 문서 편집, 설정 변경은 직접 한다.
  위임 오버헤드가 더 크다.
- 사용자가 "직접 해줘"라고 하면 직접 한다.
